title: Commands
description: Every features-cli command, what it prints and its most useful options, from scan and serve to diff, check, records, mcp and aggregate.
---

```bash
features <command> [PATH] [options]
```

`PATH` is the folder to scan for features. It defaults to the current directory, or to `path` in the [configuration file](/docs/configuration). The options of each command are listed on the [Options](/docs/options) page.

| Command                                  | Does                                                           |
| ---------------------------------------- | -------------------------------------------------------------- |
| `scan [PATH]`                            | List the features (the default command)                        |
| `serve [PATH]`                           | Serve the web dashboard, refreshed when files change           |
| `build [PATH]`                           | Build a static version of the dashboard                        |
| `codeowners [PATH]`                      | Generate or update a CODEOWNERS file                           |
| `find-owner <TARGET> [PATH]`             | Find the owner of a file or folder                             |
| `owners [PATH]`                          | List the unique owners                                         |
| `check [PATH]`                           | Validate the features against a set of rules                   |
| `records [PATH]`                         | List the specs and decision records                            |
| `new <spec\|decision> <FEATURE> <TITLE>` | Create the next numbered spec or decision record               |
| `diff [PATH] --since <ref>`              | List the features and owners touched since a git ref           |
| `mcp [PATH]`                             | Run an MCP server for AI coding agents                         |
| `aggregate <FOLDER>`                     | Combine the reports of several repositories into one dashboard |

## Explore

### scan

```bash
features scan ./src
features ./src                       # same: scan is the default
features scan ./src --json > features.json
```

Lists the features as a tree, with their owner. `--json` prints the full report (owners, stats, coverage, records, dependencies and history), `--flat` an array instead of a tree, `--description` adds the first paragraph of each README.

### serve

```bash
features serve ./src --port 4000
```

Starts an HTTP server with the web dashboard on `http://localhost:3000` (or `--port`) and rescans when files change. By default only `localhost` can read its data; `--allow-origin` opens it to another origin. `--experimental` shows the experimental pages. See [Publish the dashboard](/docs/dashboard).

### build

```bash
features build ./src --build-dir ./dashboard --strip-emails
```

Writes a static version of the dashboard (`index.html`, `features.json`, `records.json`) to `build`, or `--build-dir`, ready for any static host.

### find-owner

```bash
features find-owner src/features/auth/login.ts ./src
```

Prints the owner of a file or folder: the owner of the closest feature that contains it. The target does not need to exist.

### owners

```bash
features owners ./src --json
```

Prints the unique owners of the project, one per line.

## Ownership

### codeowners

```bash
features codeowners ./src --project-dir .
```

Writes the owner of every feature into a managed section of `CODEOWNERS`, between two markers. Lines outside the section are kept. `--codeowners-path` changes the file (default: `CODEOWNERS` in the project directory) and `--codeowners-prefix` the prefix of the owner names (default: `@`). `serve`, `build` and `check` update the file too with `--generate-codeowners`.

```text
# ==== GENERATED BY FEATURES-CLI ====
/src/features/auth @team-auth
/src/features/billing @team-billing
# ==== END SECTION GENERATED BY FEATURES-CLI ====
```

## Validate

### check

```bash
features check ./src
features check ./src --format github --enable-rule missing-readme
features check --list-rules
```

Runs the [check rules](/docs/check-rules) (duplicate names, missing owners, stale feature flags, low coverage...) and exits with code `1` when a rule set to `error` finds something. `--format` prints `text`, `json` or GitHub Actions annotations.

### diff

```bash
features diff ./src --since origin/main
features diff ./src --since origin/main --committed-only --markdown
```

Maps every file changed since the merge base of the ref and `HEAD` to its closest feature, and prints the features touched with their owners. Uncommitted changes count unless `--committed-only`. A renamed file touches both its old and new feature. `--json`, `--markdown` and `--owners-only` change the output. `--since` can be left out when `diff.since` is set in the configuration file. See [Pull requests and CI](/docs/pull-requests-ci).

## Specs and decisions

### records

```bash
features records ./
features records ./ --json
```

Lists the specs and decision records of the project and of every feature, GitHub Spec Kit and Kiro specs included. `--json` prints the project-level records as `{ "records": [...] }`. See [Specs and decisions](/docs/specs-decisions).

### new

```bash
features new spec auth "Login flow"
features new decision . "Use a monorepo"
```

Creates the next numbered record, `NNN-title.md`, in `<FEATURE>/__docs__/specs` or `/decisions`. `FEATURE` is a feature name or path, or `.` for the project-level `docs/` folder. `--path` chooses the folder to scan.

## Integrations

### mcp

```bash
features mcp ./src
```

Runs a Model Context Protocol server over stdio, so AI coding agents can query the features. See [MCP server](/docs/mcp).

### aggregate

```bash
features aggregate ./reports
```

Combines the JSON reports of several repositories into one dashboard. See [Aggregate repositories](/docs/aggregate).

## Legacy flags

Before commands existed, actions were flags: `features PATH --serve`, `--build`, `--check`, `--list-owners` and `--find-owner <TARGET>`. They still work but are deprecated, and they read the configuration file too. Combining two actions (`--serve --build`) is an error; `--generate-codeowners` can still be combined with `--serve`, `--build`, `--check` and `--list-owners`. `features PATH --since <ref>` is an alias of `features diff PATH --since <ref>`. The options of `check` (`--rule`, `--format`, `--list-rules`...) only exist on the `features check` command, not on `--check`.
